ไฟล์ที่เกี่ยว

- `public/wms-fire-config.js` — **สวิตช์ระบบใหม่** (`on`) โดเมนอีเมลบริษัท และ web config ของ Firebase
- `firebase/firestore.rules` — กฎสิทธิ์ วางใน Console
- `firebase/firestore.indexes.json` — ฟิลด์ที่ปิด index
- `apps-script/fire-backup.gs` — สำรองลง Drive ทุกคืน กู้คืน และชุดแชร์ของลิงก์ Supply chain (0.7)

หน้าสมุดสต๊อกมี 3 แบบ เลือกจากสวิตช์และท้ายลิงก์

| แบบ | เปิดยังไง | ข้อมูล |
|---|---|---|
| ระบบเดิม | สวิตช์ปิด (`on: false`) หรือยังไม่ใส่ config | Apps Script + ชีตเดิม เหมือนทุกวันนี้ |
| ระบบใหม่ | สวิตช์เปิด (`on: true`) และ config ครบ | Firebase ของบริษัท เข้าด้วย Google @lunio.co.th |
| โหมดซ้อม | ต่อท้ายลิงก์ `?fire=demo` | ข้อมูลสมมติ อยู่ในเครื่องนั้นเครื่องเดียว ไม่ถึงฐานจริง |

ต่อท้ายลิงก์เฉพาะเครื่องเดียว (ไม่ต้องแก้ไฟล์)

- `?fire=off` — เครื่องนี้ใช้ระบบเดิม จำไว้จนกว่าจะเปิด `?fire=on`
- `?fire=live` — แท็บนี้เปิดระบบใหม่แม้สวิตช์ปิด **เฉพาะหัวหน้า** (ใช้ก่อนวันขึ้นระบบ และตอนถอยกลับ)
- `?fire=demo` / `?fire=demo-reset` — โหมดซ้อม / ล้างแล้วเริ่มซ้อมใหม่

> web config ของ Firebase ไม่ใช่รหัสลับ ใครเปิดเว็บก็เห็น ความปลอดภัยอยู่ที่ Rules + ต้องเข้าด้วยอีเมลบริษัทที่หัวหน้าเพิ่มชื่อไว้
> ห้ามใส่ service account, private key หรือรหัสผ่านใด ๆ ในโปรเจกต์นี้ (repo เป็นสาธารณะ)

## 0. แอปสมุดสต๊อก (ทีม Inventory)

ระบบใหม่และโหมดซ้อมเปิดเป็นแอปของทีม Inventory แยกจากเมนู WMS อื่น มีเมนูของตัวเอง (ระบบเดิมยังเป็นหน้าเดิมทุกอย่าง)

- เมนู WMS: **สมุดสต๊อก** เป็นเมนูหลักบนสุด ถัดจาก Shift Log กับนับสต๊อก (ไม่อยู่ในกลุ่ม Inventory แล้ว)
- ไม่มีป้ายรหัสเครื่อง เข้าด้วย Google ของบริษัทแทน · ระบบเดิม (สวิตช์ปิด) ยังมีป้ายรหัสเหมือนเดิม
- โควตา Firebase นับเฉพาะหน้าสมุดสต๊อกระบบใหม่ เปิดหน้าอื่นของ WMS ไม่กินโควตา
- หน้า วันนี้ และ เอกสาร คิดจากสำเนาในเครื่อง ไม่อ่านฐานเพิ่ม (หัวหน้าเปิดหน้าวันนี้ อ่านเพิ่ม 2 ครั้ง ไม่เกินทุก 10 นาที)

### 0.1 เมนู

คอม: แถบบน 9 หมวด · เมนูซ้ายเห็นเฉพาะหมวดที่เลือก · ชื่อ สิทธิ์ และปุ่ม **ออก** อยู่ขวาบน · สถานะข้อมูลและปุ่ม **ดึงสต๊อกใหม่** อยู่ล่างซ้าย

### 0.2 หน้า วันนี้ → งานของฉัน

เปิดแอปมาเจอหน้านี้ก่อน

1. **ตารางงาน** งานละแถว ปุ่มขั้นต่อไปแถวละปุ่ม เรียงแถวแดงก่อน · ตัวกรอง **ต้องทำ · รอคนอื่น · เสร็จวันนี้**
   - ใบที่เราต้องรับ ตรวจ อนุมัติ หรือจัดการเพราะไม่รับ: ใบละแถว
   - ทุกคน: ชุดรอส่ง (ระบบส่งซ้ำเองทุก 30 วินาที ไม่บันทึกซ้ำ) · ชุดพักส่ง (ค้างจากก่อนยอดยกมา รอคนกดเอง) · ใส่เลข TRcloud (รวมแถวเดียว แดงเมื่อใบเก่าสุดค้าง 2 วัน) · ร่างค้างยังไม่บันทึก
   - หัวหน้าเห็นเพิ่ม: พบเอกสารผิดกติกา หรือตัวตรวจเสกยอดยังไม่ตั้ง / หยุด (1.10) · ยังไม่ลงยอดยกมา · ปิดเดือนได้แล้ว · ยังไม่นำเข้ายอด TRcloud หรือเก่าเกิน 7 วัน · วางแถวลงชีตเดิม (เฉพาะตอนยังวางกันอยู่ ดู 0.4)
2. **บันทึกล่าสุดวันนี้** ยอดรวมทั้งคลังแยกตามประเภท และรายการใบล่าสุด กดเลขที่เพื่อดูทั้งใบ

### 0.3.1 ตรวจ / อนุมัติ ใบย้ายและแปลง + พิมพ์ใบ

- ทุกใบในเมนู **ย้าย / เติม / QA** และ **แปลงสินค้า**: ผู้จัดทำ → ผู้ตรวจสอบ → ผู้อนุมัติ
- ยอดเปลี่ยนตั้งแต่กดบันทึก
- ย้าย / เติมในคลัง และแปลง: ใช้ของต่อได้เลย ตรวจ / อนุมัติตามหลัง
- ใบโอน QA / IQA: ผู้ตรวจสอบ = **ผู้รับ** ต้องกด **รับ** ก่อน ของจึงใช้ต่อได้ (ตารางข้างล่าง)
- ผู้ตรวจใบย้ายในคลัง / แปลง = ใครก็ได้ที่ลงรายการได้ **ยกเว้นคนทำ** · ผู้อนุมัติ = หัวหน้า หลังมีผู้ตรวจแล้ว (หัวหน้าอนุมัติใบที่ตัวเองทำได้ แต่ต้องให้คนอื่นตรวจก่อน) · หัวหน้ากด **ตรวจ + อนุมัติ** ครั้งเดียวได้
- กดได้ที่หน้าเอกสารทีละใบ หรือ **เอกสารทั้งหมด → ชิป รอตรวจ / รออนุมัติ** ติ๊กหลายใบแล้วกดทีเดียว · หน้า วันนี้ ขึ้นใบที่เรากดได้ ใบละแถว · เมนู **รอรับ / รออนุมัติ** เปิดรายการรวม
- ใบย้ายเข้า / ออก QA ที่ยังไม่อนุมัติ = **🔒 ใส่เลข TRcloud ไม่ได้ ออกไฟล์ปรับยอดไม่ได้** · แท็บย้ายไม่มีช่องเลข TRcloud ใส่หลังอนุมัติ · แปลงยังพิมพ์ MR / GR ตอนบันทึกได้เหมือนเดิม

**รับก่อนใช้ต่อ: ใบโอน QA / IQA**

| ขั้น | ใครกด | ทำอะไร | ยังไม่กด |
|---|---|---|---|
| 1 | คลัง / Inbound | ย้าย / เติม / QA → ทำใบโอนเข้า | QA ไม่มีใบให้รับ |
| 2 | ทีม QA | เอกสารทั้งหมด → **รอรับ** → นับ → **รับ** หรือ **ไม่รับ** + เหตุผล | โอนออกไม่ได้ |
| 3 | หัวหน้า | อนุมัติใบเข้า | ลง TRcloud ไม่ได้ |
| 4 | ทีม QA | ตรวจผ่าน → ย้าย / เติม / QA → **ของ QA ที่รับแล้ว** → **+ โอนออก** | ของยังอยู่ QA / IQA |
| 5 | คลัง / Inbound (ปลายทาง) | นับ → **รับ** หรือ **ไม่รับ** + เหตุผล | ขาย ย้าย แปลง ต่อไม่ได้ |
| 6 | หัวหน้า | อนุมัติใบออก | ลง TRcloud ไม่ได้ |

- ของใช้ต่อได้ทันทีที่คนรับกด ไม่ต้องรอหัวหน้า · ใบออกอนุมัติได้เมื่อใบเข้าอนุมัติแล้ว หรือเลือกอนุมัติพร้อมกัน
- มี 2 ทีม: **คลัง / Inbound** (ค่าเริ่มต้น) กับ **QA** ตั้งที่ ⚙️ ตั้งค่า → 👥 คนใช้และสิทธิ์ → ช่อง ทีม · เปลี่ยนแล้วให้คนนั้นเข้าระบบใหม่
- หัวหน้าทำและรับแทนได้ทุกทีม แต่**ไม่มีใครรับใบของตัวเองได้** · ย้ายใน QA / IQA จึงต้องมี QA คนที่สอง หรือหัวหน้า
- **ยังไม่ตั้งทีม QA = รับใบเข้า QA และทำใบออกได้เฉพาะหัวหน้า**
- ไม่รับ = ของยังพักไว้ หัวหน้า **↩ ยกเลิก** ใบนั้น ยอดกลับโลเดิม แล้วทำใบใหม่
- ใบหนึ่งมีแบบเดียว: เข้า QA · ออก QA · ย้ายใน QA · ย้าย / เติมในคลัง แยกบันทึก · ตารางแบบสมุดเดิมโอน QA ไม่ได้
- หน้า วันนี้: ต้องทำ = ค้างรับ กับไม่รับ · รอคนอื่น = ใบโอนของฉันรอคนรับ
- ยอดรายงาน (FIFO ณ วันที่ ลิงก์ Supply chain) เป็นยอดของที่อยู่จริง รวมของรอรับ
- ยังไม่คุม: หัวหน้าเบิกขาเดียวในตารางแบบเดิม (เคลม / ซ่อม) · ปรับเพิ่ม รับของ หรือคืนของเข้า QA ตรง · ใบที่ทำใน TRcloud หรือชีตตรง
- การพักของคุมในแอป · ทีม ผู้รับ ไม่รับ ขั้นตรวจ / อนุมัติ ชื่อคนทำ และล็อกเลข TRcloud คุมใน Rules ด้วย (แก้เลข TRcloud เก็บเลขเดิม คนแก้ เวลา) · แถวกับยอดในใบ Rules อ่านไม่ได้ จับย้อนหลังด้วยตัวตรวจ (1.10)

- **🖨 พิมพ์ใบ** (หน้าเอกสาร · ตารางท้ายแท็บ · ข้อความหลังบันทึก): ใบโอนย้ายสินค้า / ใบขอแปลงรหัสสินค้า A5 แนวนอน แบบเอกสารคลังสินค้าเดิม ช่องเซ็น 3 ช่อง ชื่อ + เวลาขึ้นเองเมื่อทำในระบบแล้ว · ย้ายแผ่นละ 10 แถว แปลงแผ่นละ 9 คู่ · ใบยกเลิกมีตรา ยกเลิก · โลโก้มาจากหน้าตั้งค่า
- **IQA (ของสุ่มตรวจ PO ใหม่)**: Inbound ทำใบโอนเข้า → QA กดรับ → ตรวจ → QA ทำใบโอนออก · ไม่มีใบโอนเข้าที่รับแล้ว = ออกไม่ได้
  - ออกจาก IQA ต้องใส่ **LOT และ PO** ระบบไม่เลือกกองแทน
  - ยอดใน IQA ไม่พอ = เช็ค LOT / PO แล้วแจ้ง Inbound ทำใบโอนเข้า **อย่าปรับยอด** (ใบโอนตามมาแล้วยอดซ้ำ) · ปรับเพิ่มที่ IQA ขึ้นเตือนส้ม แต่ยังบันทึกได้ (เผื่อของเจอเพิ่มจริง)
  - วันที่ออกต้องไม่ก่อนวันที่ของเข้า (วันเดียวกันได้ · ยอดยกมา = มีตั้งแต่ต้น) แถวแดงบอกวันที่ใช้ได้ · ยกเลิกใบเข้าที่มีใบออกใช้ไปแล้ว ต้องยกเลิกใบออกก่อน
  - แปลงสินค้าที่ IQA ไม่บังคับ LOT / PO (ตรวจวันที่เหมือนกัน) · กติกาตรวจในแอป ไม่ได้อยู่ใน Rules และไม่คุมใบที่ทำใน TRcloud ตรง

- ชิป: มีของ · เปิดขาย · มี QA · ติดลบ · หมดแล้ว · ทั้งหมด

  - ยอด รวม · เปิดขาย · สำรอง · QA · ติดลบ (ถ้ามี = มีแถวผิด) · Supplier · ความจุต่อพาเลท ≈ กี่พาเลท · คู่แปลง (แปลงมาจาก / แปลงเป็น พร้อมยอด กดไป SKU คู่ได้)
  - **อยู่ที่ไหน**: ทุกกองเรียงลำดับตัดแบบหน้าตัดขาย (FIFO เก่าสุดก่อน) · กองแรกที่ตัดได้มีป้าย ตัดก่อน · วันรับ + อายุ (วัน)
  - **สต๊อกการ์ด**: ทุกรายการตั้งแต่ยอดยกมา ใหม่สุดก่อน จำนวน + คงเหลือหลังแต่ละรายการ · ปุ่ม **การ์ด** ที่กอง = เฉพาะโลนั้น · กดเลขที่ = เปิดใบ แล้ว ‹ กลับไปหน้าสินค้า · ใบยกเลิกกับใบกลับรายการแสดงทั้งคู่ · 📋 คัดลอกการ์ด วาง Excel
- ลิงก์ลงท้าย `#sku=รหัส` ส่งต่อได้ · คิดจากสำเนาในเครื่อง ไม่กินโควตา

### 0.3.3 หน้า ข้อมูลหลัก (Location · SKU · กลุ่มสินค้า · แปลงสินค้า · Supplier · SKU : Pallet · โซนแร็ค)

- 7 แท็บ ตารางเดียวแก้ได้แบบ Excel (จอแคบ แท็บเลื่อนข้างได้): พิมพ์ในช่อง · Enter / ↑ ↓ เลื่อนแถว · ตัวเลขข้างชื่อแท็บ = แถวที่ต้องแก้ · จุดส้ม = มีที่แก้ยังไม่บันทึก
  - **Location** — รหัส · จุ (พาเลท ว่าง = ไม่จำกัด) · ใช้งาน · หมายเหตุ · ระบบบอกชนิด (แร็ค ชั้นไหน / พื้น / ชั้นวาง / พิเศษ) กับของตอนนี้
  - **SKU** — SKU · SKU เต็ม · ชื่อ · กลุ่มสินค้า · ของแถม · สุญญากาศ · ใช้งาน (Supplier ไม่อยู่ที่นี่ ผูกกับ PO ตามตาราง PO. Truck)
  - **กลุ่มสินค้า** — ขึ้นแร็คได้ไหม · ชั้นแร็ค (ชั้น 1 / ชั้น 2 ขึ้นไป / ทุกชั้น) · เศษ / ไม่ขึ้นแร็คไปที่ · ค่าเริ่ม = กติกาที่เก็บ 9 พ.ย. (หมอน เครื่องนอน Sofa Bed รอหัวหน้ายืนยัน)

  - **SKU : Pallet** — SKU · Product ID · ชิ้นต่อพาเลท · **ขึ้นแร็ค** (แทนชีต `ความจุต่อพาเลท`) · ระบบโชว์ชื่อ ของตอนนี้ ≈ กี่พาเลท และ *ระบบวางที่* · แถวที่ว่างทั้งชิ้นและขึ้นแร็คไม่บันทึก
    - ขึ้นแร็ค: **ตามกลุ่ม** = ค่าเริ่ม · **ได้** / **ไม่ได้** = เฉพาะ SKU ที่ต่างจากกลุ่ม (เช่น กล่องใหญ่เกินช่อง) · มาก่อนกติกากลุ่มทั้งตอน 🎯 เลือกโลให้ และคำเตือนตอนวางเข้า R
    - ไม่ได้ → พื้น / ชั้นวางที่กลุ่มตั้งไว้ (กลุ่มตั้ง RIB หรือแร็ค = พื้น A–C) · ไม่ต้องใส่ชิ้นต่อพาเลท

    - นำเข้าไฟล์ที่ไม่มีคอลัมน์ `ขึ้นแร็ค` = คงค่าที่ตั้งไว้ · มีคอลัมน์ = ตามไฟล์ (ได้ / ไม่ได้ / ตามกลุ่ม หรือเว้นว่าง)
    - ก่อนตั้งครั้งแรก: ให้หัวหน้าทุกคนรีเฟรชหน้า (Ctrl+F5) · หน้ารุ่นเก่าที่เปิดค้างถ้าบันทึกแท็บนี้ ค่าขึ้นแร็คราย SKU จะหาย
  - **โซนแร็ค** — แร็คจาก · แร็คถึง · ชั้นจาก · ชั้นถึง · โฟกัสกลุ่ม (ดูหัวข้อ *โซนแร็คและระบบเลือกแร็ค* ด้านล่าง)
- **ตั้งล่วงหน้าได้ ไม่ต้องรอยอดยกมา** (หัวหน้า เปิด `?fire=live` ตอนสวิตช์ยังปิด · หัวตารางมีป้าย **⏳ ก่อนยอดยกมา**)

  2. **SKU** วางจาก Excel (SKU · SKU เต็ม · ชื่อ · กลุ่ม) → 💾

  4. **แปลงสินค้า · Supplier · SKU : Pallet** 📂 นำเข้าไฟล์ → 💾 ทีละแท็บ
  5. **โซนแร็ค** ไม่บังคับ → 💾
  6. ตั้งเสร็จ กด **คัดลอกไป Excel** เก็บไว้ทีละแท็บ: ก่อนลงยอดยกมา สคริปต์สำรองทุกคืนยังไม่เก็บอะไร
  - ไม่สร้างเอกสาร ไม่กินเลขเอกสาร · ลงยอดยกมาแล้วทุกเครื่องได้ตารางเองครบ ไม่ต้องบันทึกซ้ำ
  - ช่วงนี้คอลัมน์ *ของตอนนี้* ยังเป็น 0 และทุกช่องแร็คนับเป็นว่าง · หัวหน้าคนอื่นเห็นที่เพิ่งบันทึกเมื่อเปิดหน้านี้ใหม่
  - **ลงเอกสารล็อกไว้จนกว่าจะลงยอดยกมา** (ป้าย 🔒 ที่แถบบันทึก รวมรับของเพื่อลอง 🎯 เลือกโลให้ และยกเลิกใบ) · จะลอง ใช้แท็บ โซนแร็ค → 🎯 ลองเลือกแร็ค หรือ `?fire=demo`

- แท็บ Supplier / SKU : Pallet มี **+ เพิ่มทั้งหมด** เหมือนกัน: PO ในสมุดที่ยังไม่มี Supplier · SKU (ตามตาราง SKU) ที่ยังไม่มีชิ้นต่อพาเลท → ใส่ช่องที่ว่างแล้วบันทึก
- **📂 นำเข้าไฟล์** (แท็บ แปลงสินค้า · Supplier · SKU : Pallet) หรือลากไฟล์มาวางในหน้านี้: ไฟล์ Excel ที่มีชีต `PO. Truck` · `MASTER แปลงสินค้า` · `ความจุต่อพาเลท` · ชีตไหนมี ตารางนั้น **แทนร่างทั้งตาราง** (ยังไม่บันทึก) ขึ้นว่าเพิ่ม / แก้ / ลบ กี่แถว → ตรวจ → 💾 บันทึก **ทีละแท็บ**
  - หน้า **TRcloud → นำเข้า** ยังรับไฟล์เดียวกันได้ แต่ตารางหลักไม่บันทึกที่นั่นแล้ว: กด **🗂 ตรวจใน ข้อมูลหลัก** = ส่งมาหน้านี้ (ยอด TRcloud ในไฟล์เดียวกันยังบันทึกที่หน้า TRcloud)
  - วางจาก Excel ที่มีหัวตาราง (เช่นคัดลอกทั้งชีต PO. Truck ที่คอลัมน์เป็น Truck · PO.) ระบบอ่านตามหัวให้ · ไม่มีหัว = ตามลำดับคอลัมน์ในหน้า
  - ⚠ แดง: คู่แปลงซ้ำ / SKU เดียวกันทั้งสองช่อง · PO ซ้ำ · ความจุไม่ใช่ตัวเลข · ขึ้นแร็คอ่านไม่ออก · ส้ม: ยังไม่ใส่ Supplier / ความจุ (ข้ามแถวนั้น) · ข้อมูล: Supplier เขียนต่างกัน (เช่นเว้นวรรคไม่เหมือนกัน) · ไม่มีในตาราง SKU
  - สามตารางนี้ไม่มีสวิตช์ เตือน | ห้ามบันทึก (ไม่ได้ใช้ตอนลงใบ)
- **⚡ สร้างหลายช่อง** (Location): แร็ค จาก–ถึง × ช่อง × ชั้น · จำนวนหลักตาม *ตัวอย่างรหัส* (ดึงจากโลแร็คที่มีอยู่) · ช่องที่มีแล้วข้าม
- วางจาก Excel: Ctrl+V ที่ไหนก็ได้ (ไม่อยู่ในช่อง) = เพิ่มแถว / อัปเดตแถวที่รหัสตรง (อัปเดตเฉพาะช่องที่วางมา ไม่ว่าง) · วางในช่อง = ทับจากช่องนั้นลงไป · **คัดลอกไป Excel** ได้ทั้งตาราง
- ⚠ แดง = บันทึกไม่ได้ (รหัสซ้ำ / ว่าง) · ส้ม = ควรแก้ (แร็ค R เกิน 1 พาเลท · ยังไม่มีกลุ่ม · ปิดใช้แต่ยังมีของ …) · โล / SKU ที่ยังมีของลบไม่ได้ ให้เอาติ๊ก **ใช้งาน** ออก · กลุ่มที่ยังมี SKU ลบไม่ได้
- ที่แก้ค้างอยู่ในเครื่องนั้นจนกด 💾 บันทึก หรือ **ยกเลิกที่แก้** · บันทึกทั้งตารางครั้งเดียว ทุกเครื่องได้ตารางใหม่ตอนดึงรอบถัดไป · 🕘 **ประวัติ** เก็บ 60 ครั้งล่าสุด (ใคร เมื่อไร เพิ่ม / แก้ / ลบอะไร)
- หัวหน้าสองคนแก้ตารางเดียวกันพร้อมกัน: คนที่บันทึกทีหลังขึ้น *มีคนบันทึกก่อนแล้ว* → **โหลดตารางใหม่** (ที่แก้ไว้หาย) หรือ **ใช้ร่างของฉันทับ**

ตอนลงใบ (รับของ · ย้าย · คืน · แปลง · ปรับยอด · ตารางแบบเดิม — ไม่รวมตัดขาย)

- โล / SKU ที่ไม่มีในตาราง หรือปิดใช้ = เตือนสีส้ม บันทึกได้ (แทนข้อความเดิม *ไม่เคยมีในสมุด*)
- แต่ละตารางตั้งได้ **ไม่มีในตาราง: เตือน | ห้ามบันทึก** · ห้ามบันทึก = แถวแดง ต้องแก้ก่อน (หรือหัวหน้าเพิ่มในตารางก่อน) · แนะนำเตือนไปก่อนจนตารางครบ
- วางของเข้าแร็ค R ผิดกติกากลุ่ม (เช่น ท็อปเปอร์ลง R ชั้น 1 · ที่นอน 6 ฟุตขึ้นชั้น 2) = เตือนเสมอ ไม่ห้าม

- ต้องมีก่อน: ตาราง **Location** ครบทุกช่องรวมช่องที่ว่าง (**+ เพิ่มทั้งหมด** ได้แค่โลที่เคยอยู่ในสมุด ช่องที่เหลือใช้ **⚡ สร้างหลายช่อง**) · **SKU** มีกลุ่ม · **SKU : Pallet** มีชิ้นต่อพาเลท (ตัวที่ไม่ขึ้นแร็คไม่บังคับ)
- โซน = ช่วงแร็คที่กลุ่มหนึ่งได้ก่อน **ไม่ได้ห้ามกลุ่มอื่น** · ไม่ตั้งโซนเลยก็ใช้ได้
  - แร็คถึงว่าง = แร็คเดียว · ชั้นว่างทั้งสองช่อง = ทุกชั้นที่กลุ่มนั้นใส่ได้ · โซนทับกัน = แถวบนใช้ก่อน (แถวใหม่ต่อท้าย)
- ลำดับช่องที่ระบบเลือก: โซนของกลุ่ม → ช่องที่ไม่อยู่ในโซน → โซนกลุ่มอื่น (เฉพาะเมื่อสองแบบแรกเต็ม) · เฉพาะชั้นที่กลุ่มใส่ได้ · เรียงแร็ค ช่อง ชั้น
- พาเลทเต็มลงช่องละ 1 · เศษตามกลุ่ม: RIB / ช่องของตัวเอง (แร็คเต็มลงพื้น A–C) / พื้น A–C / พื้น D / ชั้นวาง S · พื้นรวมกองเดิมเฉพาะ SKU LOT PO เดียวกัน และไม่เกิน **จุ** ที่ใส่ไว้
- **ลองก่อน:** แท็บ โซนแร็ค → **🎯 ลองเลือกแร็ค** ใส่ SKU กับชิ้น → เห็นช่องที่จะได้กับผังแร็ค (ใช้ร่างที่ยังไม่บันทึกได้)
- **ใช้จริง:** แท็บ รับของ → ใส่ SKU · LOT · PO · ชิ้น เว้น โลที่วาง → **🎯 เลือกโลให้** → แตกเป็นแถวละพาเลท → ตรวจ / แก้ → บันทึก
  - แถวที่ใส่โลเองไม่เปลี่ยน · ข้อมูลไม่พอหรือที่ไม่พอ = เว้นโลไว้และบอกเหตุผล ไม่เดา · ใช้ตารางที่ **บันทึกแล้ว** เท่านั้น
  - ช่องที่เลือกยังไม่ถูกจองในฐานจนกดบันทึก: คนอื่นใช้ไปก่อน แถวขึ้นเตือนหลังดึงสต๊อกรอบถัดไป
- หน้า **จัดที่เก็บ** (แผนทั้งตู้) ยังใช้กติกาของหน้านั้นเอง ไม่อ่านโซนแร็ค และไม่อ่านช่อง ขึ้นแร็ค ราย SKU

### 0.4 ปิดวัน / เดือน และ ตั้งค่า

งานหัวหน้าที่ทำเป็นรอบอยู่ใน **ปิดวัน / เดือน** เรียงตามลำดับ

| | ทำเมื่อไร | ทำอะไร |
|---|---|---|
| ① ตรวจยอด | เช้า / ก่อนกลับ | **🔍 ตรวจยอดตอนนี้** คิดยอดใหม่จากเอกสารทุกใบ เทียบยอดในเครื่อง ต้อง ✓ |
| ② วางชีตเดิม | **ไม่บังคับ** · ตอนถอยกลับ (หัวข้อ 4) | 📋 คัดลอก แถวของวัน → วางท้ายชีต Transaction เดิม → **✓ วางแล้ว** · หน้ารายงานอ่านระบบใหม่แล้ว (0.6) ไม่ต้องวางทุกวัน · กดวางแล้วสักวัน หน้า วันนี้ จะเตือนวันที่ยังไม่วาง |
| ③ ปิดเดือน | ทุกต้นเดือน | หัวข้อ 5 |

**ตั้งค่า**: หัวหน้า = 👥 คนใช้และสิทธิ์ · 📥 ยอดยกมา · 💾 สำรอง · 📊 โควตาฟรี · คนลงรายการ = 🔍 สำเนาเครื่องนี้ · 📊 โควตาฟรี

### 0.5 ติดตั้งเป็นแอป (ไม่บังคับ)

ได้ไอคอน **สมุดสต๊อก** บนเดสก์ท็อป / หน้าจอโทรศัพท์ เปิดเป็นหน้าต่างแยก ไม่มีแถบที่อยู่เว็บ

- คอม (Chrome / Edge): เปิด `https://<เว็บ>/book/` → ไอคอนติดตั้ง (จอ + ลูกศร) ท้ายช่องที่อยู่เว็บ หรือ ⋮ → **ติดตั้งสมุดสต๊อก**
- Android (Chrome): ⋮ → **ติดตั้งแอป** หรือ **เพิ่มลงในหน้าจอหลัก**
- iPhone (Safari): ปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม** (iPhone เก็บข้อมูลแยกจาก Safari ต้องเข้าระบบใหม่ในแอปครั้งแรก)

- แอปเปิดตามสวิตช์: ก่อนเปิดสวิตช์ (ก่อน 21 ธ.ค.) จะเป็นหน้าสมุดแบบเดิม · เว็บอัปเดต แอปก็อัปเดตเอง ไม่ต้องติดตั้งใหม่
- กด **เข้าสู่ระบบด้วย Google** ในแอปแล้วหน้าต่างไม่ขึ้นหรือค้าง → ใช้ผ่านเบราว์เซอร์แทน (ลิงก์เดิม ทำงานเหมือนกันทุกอย่าง)

### 0.6 หน้ารายงานอ่านจากระบบใหม่

สวิตช์เปิดแล้ว หน้ารายงานในเมนู WMS คิดตัวเลขจากเอกสารในระบบใหม่ทั้งหมด **ไม่อ่านชีต Transaction เดิม** ไม่ต้องตั้ง URL Transaction

| หน้า | ได้อะไรจากระบบใหม่ |
|---|---|
| ภาพรวมสต๊อก · สต๊อกราย Location · FIFO สต๊อก · คงเหลือ ณ วันที่ · จัดที่เก็บ · ความเสี่ยง MFG | ยอดคงเหลือ ราย LOT/PO/โล วันรับ ยอดขาย ข้อมูลผิด ประวัติ SKU |
| LOT/PO ขายออก · เช็คตัดสต๊อก | แถวขายรายวัน (ฝั่งไฟล์ออเดอร์ / ไฟล์ตัดสต๊อก ยังเป็นสคริปต์ของหน้านั้นเหมือนเดิม) |

- แถบบนสุด **📒 อ่านจากระบบใหม่ · ชื่อคนเข้า** = ตัวเลขมาจากระบบใหม่ · ยังไม่เข้าระบบ = แถบเหลือง กด **เข้าสู่ระบบด้วย Google** (บัญชีเดียวกับแอปสมุดสต๊อก เข้าแล้วหน้าโหลดใหม่เอง)
- เปิดหน้ารายงาน = ดึงเฉพาะเอกสารใหม่จากฐาน (เครื่องเดียวกับแอปใช้สำเนาเดียวกัน) · มีคนบันทึกเพิ่ม หน้าที่เคยขึ้นชุดใหม่ให้เอง (ภาพรวม FIFO ยอด ณ วันที่ …) ยังขึ้นเองภายในนาที · 🔄 ดึงใหม่ = ดึงทันที
- Supplier / คู่แปลง / ความจุต่อพาเลท มาจากตารางหลักในหน้า **สมุดสต๊อก → ข้อมูลหลัก** (0.3.3) ยังไม่ตั้ง หน้าจะบอกให้ตั้ง
- เลข **แถว** ในหน้ารายงาน = ลำดับแถวในสมุดของระบบใหม่ (ไม่ใช่แถวในชีต) · ประวัติ SKU บอกเลขที่เอกสารด้วย
- ยังใช้ของเดิม (รอขั้นต่อไป)
  - **นับสต๊อกใหญ่** ยังอ่านชีตเดิม: นับ 19–20 ธ.ค. และทำไฟล์ตั้งต้นสมุดจากชีตเดิม
  - **นับสต๊อกรายวัน** (แท็บ นับสต๊อก ในสต๊อกราย Location และการ์ดนับสต๊อกในภาพรวม) ยังเป็นสคริปต์ tx-api.gs ที่คิดยอดจากชีตเดิม — ถ้ายังนับรายวันหลัง 21 ธ.ค. ต้องวางชีตเดิมทุกวัน (0.4 ②) ไม่งั้นพักนับรายวันไว้ก่อน
  - **ความเสี่ยง MFG** ยอดตั้งต้นของรอบมาจากระบบใหม่แล้ว แต่ผลนับ คำตัดสิน และหน้าหัวหน้า (ลิงก์เจ้านาย) ยังเก็บในไฟล์ของสคริปต์นับสต๊อก (stocktake-api.gs) — ไม่อ่านชีต Transaction ใช้ต่อได้เหมือนเดิม
- ลิงก์ FIFO ของ Supply chain (ไม่ต้องเข้าระบบ) อ่านชุดแชร์ของระบบใหม่ได้แล้ว → ตั้งตาม 0.7
- ระบบใหม่ปิด / เครื่องที่เปิด `?fire=off` = หน้ารายงานกลับไปอ่านชีตเดิมเหมือนก่อน (ไม่มีแถบ)

### 0.7 ลิงก์ Supply chain (รายงาน FIFO ไม่ต้องเข้าระบบ)

คนนอกทีม (Supply chain) เปิดดูรายงาน FIFO และดาวน์โหลด Excel ได้โดยไม่ต้องเข้าระบบ · ตัวเลขมาจากระบบใหม่ ไม่อ่านชีตเดิม

- สคริปต์สำรอง `fire-backup.gs` ทำ **ชุดแชร์** ทุก 2 ชั่วโมง (ไฟล์ `wms-fire-share.txt` ในโฟลเดอร์สำรอง) → หน้าลิงก์คิด FIFO เองด้วยสูตรเดียวกับหน้าในแอป
- ชุดแชร์มีแค่แถวสต๊อกกับตารางหลัก **ไม่มีชื่อคน อีเมล ออเดอร์** · ไม่มีอะไรใหม่ อ่านฐาน 1 ครั้งต่อรอบ (ไม่กินโควตา)
- ตัวเลขในลิงก์ช้ากว่าหน้าในแอปได้ไม่เกิน 2 ชั่วโมง (ดู **🕐 ดึงเมื่อ** บนหน้า)

ตั้งครั้งเดียว (หัวหน้า บัญชี Owner เดียวกับข้อ 1.9)

1. วาง `fire-backup.gs` ใหม่ทั้งไฟล์ → ใส่ `FIREBASE_PROJECT_ID` เดิม → Ctrl+S (appsscript.json ไม่ต้องแก้)
2. เลือกฟังก์ชัน `installShare` → เรียกใช้ → บันทึกการดำเนินการขึ้น
   - ก่อนลงยอดยกมา: *ตั้งเวลาทำชุดแชร์ทุก 2 ชั่วโมงแล้ว* + *ยังไม่มีอะไรให้แชร์* = **สำเร็จ** ยังไม่มีไฟล์เป็นเรื่องปกติ (หลังลงยอดเรียก `shareRefresh` หนึ่งครั้งก่อนทำข้อ 4)
   - หลังลงยอดยกมา: *ชุดแชร์ wms-fire-share.txt · เอกสารใหม่ … ใบ*
3. **ทำให้ใช้งานได้ (Deploy)** → **การทำให้ใช้งานได้รายการใหม่** → ⚙️ ประเภท **เว็บแอป** → ดำเนินการในฐานะ **ฉัน** · ผู้มีสิทธิ์เข้าถึง **ทุกคน** → ทำให้ใช้งานได้ → คัดลอก **URL ของเว็บแอป** (ลงท้าย `/exec`)
4. หน้า **FIFO สต๊อก** (เห็นแถบ 📒 อ่านจากระบบใหม่) → ปุ่ม **⚙** ข้าง 🔗 ลิงก์ Supply chain → วาง URL → **ทดสอบและบันทึก** → ขึ้น *✅ บันทึกแล้ว · ชุดแชร์ล่าสุด …*
5. กด **🔗 ลิงก์ Supply chain** → ได้ลิงก์ในคลิปบอร์ด → ส่งทาง LINE / อีเมล ให้ทีม Supply chain

- URL ที่ตั้งเก็บในเครื่องนั้นเครื่องเดียว (เครื่องอื่นที่จะกดส่งลิงก์ ทำข้อ 4 ซ้ำ หรือกู้จากไฟล์กุญแจของหน้าตั้งค่า)
- วาง URL สคริปต์ Transaction เดิมในข้อ 4 ไม่ได้ (ขึ้น ❌ ไม่ใช่เว็บแอปของ fire-backup.gs)
- อัปเดตสคริปต์ทีหลัง: วางไฟล์ใหม่ + ใส่ `FIREBASE_PROJECT_ID` เดิม → **จัดการการทำให้ใช้งานได้** → ✏️ แก้ไข → เวอร์ชัน **ใหม่** → ทำให้ใช้งานได้ (URL เดิม ลิงก์ที่ส่งไปแล้วใช้ต่อได้)
- ลิงก์หลุดไปคนนอก: จัดการการทำให้ใช้งานได้ → **เก็บถาวร** ตัวเดิม → ทำรายการใหม่ (ข้อ 3) ได้ URL ใหม่ → ข้อ 4–5 ส่งลิงก์ใหม่ (ลิงก์เก่าเปิดไม่ได้อีก)
- ลิงก์เก่าที่ส่งก่อนขึ้นระบบ (อ่านสคริปต์ Transaction) ยังเปิดได้ แต่ตัวเลขหยุดที่ชีตเดิม → วันขึ้นระบบส่งลิงก์ใหม่แทน
- ลิงก์ขึ้น *ข้อมูลยังไม่พร้อม* = ยังไม่ได้ทำข้อ 2 หรือยังไม่มีชุดแชร์หลังลงยอดยกมา (เรียก `shareRefresh`) · เบราว์เซอร์เก่ามาก (ก่อนปี 2023) ขึ้น *เปิดรายงานไม่ได้* ให้ใช้ Chrome / Edge / Safari รุ่นใหม่

## 1. ตั้งค่า Firebase (ทำครั้งเดียว)

ใช้บัญชี **@lunio.co.th** เท่านั้น ห้ามใช้ Gmail ส่วนตัว ระบบจะได้เป็นของบริษัท

> **หาเมนูไม่เจอ** (Firebase เปลี่ยนหน้าตาเมนูซ้ายบ่อย ชื่อหมวดอาจไม่ใช่ Build): ใช้ลิงก์ตรงแทน
> เข้าโปรเจกต์แล้วดูช่องที่อยู่เว็บ จะเป็น `console.firebase.google.com/project/<รหัสโปรเจกต์>/overview`
> เปลี่ยนคำท้าย `overview` เป็น `firestore` (ฐานข้อมูล) หรือ `authentication` (เข้าระบบด้วย Google) แล้วกด Enter
> หรือเมนูซ้ายกด **All products** (หรือไอคอน ☰ ถ้าเมนูซ่อนอยู่) แล้วหาการ์ดชื่อ Firestore / Authentication

### 1.1 สร้างโปรเจกต์

1. เปิด https://console.firebase.google.com ด้วยบัญชีบริษัท
2. **Create a project** → ตั้งชื่อ เช่น `lunio-wms` → ถ้าถามองค์กร เลือก **lunio.co.th**
3. Google Analytics: **ปิด** (ไม่ใช้) → **Create project**
4. ดูมุมซ้ายล่างต้องเป็นแผน **Spark** (ฟรี) — **ห้ามกดอัปเกรดเป็น Blaze**
   แผนฟรีเกินโควตาไม่มีบิล แค่บันทึกไม่ได้จนโควตาเริ่มใหม่ (15:00 เวลาไทยช่วงหน้าหนาว 14:00 ช่วง มี.ค.–พ.ย.)
5. ให้ IT เพิ่มคุณและหัวหน้า Inventory เป็น **Owner** ของโปรเจกต์ (⚙️ Project settings → Users and permissions)

### 1.2 ฐานข้อมูล Firestore

1. เมนูซ้าย **Firestore Database** (ลิงก์ตรง `…/project/<รหัสโปรเจกต์>/firestore`) → **Create database**
2. Edition: **Standard** · Database ID: ปล่อยเป็น **(default)** (ฐานที่ตั้งชื่อเองไม่ได้โควตาฟรี)
3. Location: **asia-southeast1 (Singapore)** — เปลี่ยนทีหลังไม่ได้
4. เลือก **Start in production mode** → **Create**

### 1.3 วางกฎ (Rules)

1. Firestore Database → แท็บ **Rules**
2. ลบของเดิมทั้งหมด → เปิดไฟล์ `firebase/firestore.rules` คัดลอกทั้งไฟล์มาวาง
3. เช็คบรรทัด `matches('.*@lunio[.]co[.]th')` ต้องเป็นโดเมนบริษัท → **Publish**
4. ไฟล์ Rules เปลี่ยนเมื่อไร ทำข้อ 1–3 ใหม่ทั้งไฟล์ (ล่าสุด 22 พ.ย. 69: รับก่อนใช้ต่อ ทีม QA ไม่รับ ล็อกเลข TRcloud + ปิดช่องเขียนปลอมขั้น 0 + รหัสชุดและจำนวนส่วน)
   - ลำดับ: **push เว็บให้เขียวก่อน → วาง Rules → ทุกเครื่องรีเฟรช** (Rules ใหม่ไม่รับใบโอน QA จากหน้าเว็บรุ่นเก่า)
   - ไม่วางใหม่ = ปุ่มไม่รับ การแก้เลข TRcloud เดิม การปิดเดือน และผลตัวตรวจขึ้นไม่มีสิทธิ์ · กฎใหม่ทุกข้อข้างล่างยังไม่มีผล
   - หน้าเว็บรุ่นเก่าที่เปิดค้าง แก้เลข TRcloud เดิมและปิดเดือนไม่ได้ → รีเฟรช
   - วางแล้วทำข้อ 1.10 ต่อ (วาง `fire-backup.gs` ชุดใหม่ด้วย)

### 1.3.1 ทดสอบ Rules ก่อนให้คนลงรายการเข้า

  1. ลงยอดยกมา · บันทึกครบทุกประเภท · ใบใหญ่ 7 ส่วน
  2. รับ / ตรวจ / อนุมัติทีละ 10 ใบ · แก้เลข TRcloud ทีละ 10 ใบ (ดูว่าไม่ชนเพดาน 1,000 นิพจน์ต่อคำขอ)

หลัง push config ขึ้นเว็บแล้ว (GitHub Actions เขียว)

1. หัวหน้าเปิด `https://<เว็บ>/book/?fire=live` → **เข้าสู่ระบบด้วย Google ของบริษัท** → ต้องเห็นป้ายแดง *สวิตช์ปิดอยู่ · หัวหน้าเปิดดูระบบใหม่*
2. **วาง Rules ชุดใหม่และทดสอบแล้วเท่านั้น (1.3, 1.3.1)** → ⚙️ ตั้งค่า → 👥 คนใช้และสิทธิ์ → เพิ่มทุกคนด้วยอีเมลบริษัท + สิทธิ์ (หัวหน้า / ลงรายการ / ดูอย่างเดียว) + ทีมของคนลงรายการ (คลัง / Inbound หรือ QA)
3. ให้แต่ละคนเปิดลิงก์เดียวกันแล้วกดเข้า ถ้าขึ้น *สวิตช์ระบบใหม่ปิดอยู่ ใช้หน้าสมุดสต๊อกแบบเดิม* = **บัญชีใช้ได้แล้ว** (ขึ้นอย่างอื่น = ยังไม่ได้เพิ่มชื่อ หรือใช้บัญชีผิด)

> **สวิตช์ปิดไม่ได้กันฐาน**: คนที่มีชื่อเป็นลงรายการเขียนเข้าฐานตรงได้เท่าที่ Rules ยอม จึงยังไม่เพิ่มคนลงรายการจนกว่าจะผ่านข้อ 1.3.1
>
> **ก่อน 21 ธ.ค. ในฐานจริงทำแค่สองอย่าง: เพิ่มคน กับตั้งข้อมูลหลัก (0.3.3)** — ห้ามบันทึกเอกสาร ห้ามลงยอดยกมา ห้ามนำเข้ายอด TRcloud
> **การลงเอกสารล็อกไว้เองจนกว่าจะมียอดยกมา** · ปุ่มลงยอดยกมา**ไม่ได้ล็อก** อย่ากดก่อนนับใหญ่เสร็จ
> - ล็อกอยู่ที่หน้าเว็บ ไม่ได้อยู่ใน Rules: หัวหน้าที่เปิดหน้าค้างไว้ก่อนอัปเดต ต้อง Ctrl+F5 ก่อนใช้ต่อ
> - ชุดที่ส่งค้างจากระบบเดิม เปิด `?fire=live` แล้วขึ้น **⏸ พักส่ง** = ไม่ส่งเข้าฐานจริง ไม่ทิ้ง · เปิดหน้าแบบปกติ (สวิตช์ยังปิด) = ส่งเข้าระบบเดิมต่อเอง
> - ลงยอดยกมาแล้วยังเหลือ **⏸ พักส่ง** = ไม่ส่งเอง: ยอดที่นับรวมชุดนั้นแล้วกด *ทิ้งชุดนี้* ยังไม่รวมกด *↻ ส่งอีกครั้ง*
> ฐานจริงจะเริ่มนับเลขเอกสาร และลบจากหน้าเว็บไม่ได้ · อยากลองบันทึกให้ใช้โหมดซ้อม `?fire=demo`
> ถ้าเผลอบันทึกไปแล้ว แจ้ง Claude ก่อน 19 ธ.ค. เพื่อล้าง `docs` กับ `meta` ใน Console ก่อนลงยอดยกมาจริง (**อย่าลบ `master`** ข้อมูลหลักที่เตรียมไว้อยู่ที่นั่น)

ล็อกอินไม่ผ่าน ขึ้นข้อความอังกฤษ:
- มีคำว่า `unauthorized-domain` → ข้อ 1.5 ข้อ 3 ยังไม่ได้เพิ่มโดเมนเว็บ
- มีคำว่า `referer` หรือ `API key` / `blocked` → ข้อ 1.6 ข้อ 4 รายชื่อเว็บของ key ไม่ครบ (ต้องมีทั้ง github.io และ firebaseapp.com)
- ปุ่มกดแล้วไม่มีหน้าต่างขึ้น → เบราว์เซอร์บล็อกป๊อปอัป ให้อนุญาตป๊อปอัปของเว็บนี้

### 1.9 สำรองทุกคืน

ทำตามหัวไฟล์ `apps-script/fire-backup.gs` (ใช้บัญชี Owner ของโปรเจกต์)

1. script.google.com → โปรเจกต์ใหม่ (ไม่ผูกชีต) → วางไฟล์ทั้งไฟล์
2. **ห้ามข้าม** ⚙️ (เมนูซ้าย การตั้งค่าโปรเจกต์) → ติ๊ก **แสดงไฟล์ Manifest "appsscript.json" ในเครื่องมือแก้ไข**
   → กลับไป `< >` เครื่องมือแก้ไข → เปิดไฟล์ `appsscript.json` → ลบของเดิมทั้งหมด วางก้อน `{ … }` จากหัวไฟล์สคริปต์ (ต้องมีบรรทัด `auth/datastore`) → Ctrl+S
3. ใส่ `FIREBASE_PROJECT_ID` = Project ID จากข้อ 1.6 → Ctrl+S
4. เรียกใช้ `installBackup` → อนุญาตสิทธิ์ (ขึ้น *Google ยังไม่ได้ยืนยันแอปนี้* → ขั้นสูง → ไปที่ … ) → ดู **บันทึกการดำเนินการ**
   - ก่อนลงยอดยกมา: *ตั้งเวลาสำรองทุกคืน 2:00 แล้ว* + *ยังไม่มี meta/head … ไม่มีอะไรให้สำรอง* = **สำเร็จ**
     ยังไม่มีโฟลเดอร์และไฟล์เป็นเรื่องปกติ (หัวไฟล์สคริปต์ข้อ 5 หมายถึงหลังลงยอดแล้ว) · **อย่าลงยอดยกมาเพื่อให้มีไฟล์**
   - หลังลงยอดยกมา: เรียก `backupNightly` หนึ่งครั้ง หรือรอคืนแรก → Google Drive มีโฟลเดอร์ **WMS ระบบใหม่ สำรอง** + ไฟล์แรก (ข้อมูลหลักที่ตั้งล่วงหน้าอยู่ในไฟล์นี้ครบ)

สคริปต์ไม่เปิดชีตใดเลย ไม่แก้เอกสาร · เขียนฐานจริงที่เดียวคือ `audit/last` (ผลตรวจ 1.10)

อัปเดตสคริปต์ (เช่น 21 พ.ย. 69 เก็บการตรวจ / อนุมัติ): วางไฟล์ใหม่ทั้งไฟล์ → ใส่ `FIREBASE_PROJECT_ID` เดิม → Ctrl+S · appsscript.json กับเวลาตี 2 ไม่ต้องทำใหม่

ขึ้น `Firestore 403` + `ACCESS_TOKEN_SCOPE_INSUFFICIENT` = ข้าม appsscript.json (ข้อ 2) → ทำข้อ 2 แล้วเรียกใช้ `installBackup` ใหม่ จะมีหน้าต่างขออนุญาตเพิ่ม กดอนุญาต (ตั้งเวลาซ้ำไม่ได้ สคริปต์ลบของเดิมก่อนเอง)
ขึ้น `403` แบบอื่น เช่น `PERMISSION_DENIED` ไม่มีคำว่า SCOPE = บัญชีที่รันไม่ใช่ Owner / Editor ของโปรเจกต์ Firebase

### 1.10 ตัวตรวจเสกยอด (แจ้งหัวหน้า)

Rules อ่านแถวในใบไม่ได้ สคริปต์จึงไล่ตรวจใบใหม่ทุกราว 2 ชั่วโมง **จับได้ แต่กันไม่ได้**

1. วาง Rules ชุดใหม่แล้ว (1.3)
2. โปรเจกต์สคริปต์เดิมของ 1.9 → วาง `fire-backup.gs` ชุดใหม่ทั้งไฟล์ → ใส่ `FIREBASE_PROJECT_ID` เดิม → Ctrl+S
3. เรียกใช้ `installAudit` → บันทึกขึ้น *ตั้งเวลาตรวจแถวทุก 2 ชั่วโมงแล้ว* (ทำก่อนลงยอดยกมาได้ · ไม่ต้องแก้ appsscript.json)

หน้า **วันนี้** ของหัวหน้า

| แถวในงานของฉัน | ทำอะไร |

## 4. แผนถอยกลับชีตเดิม

### เมื่อไรถอย

ตัดสินโดยหัวหน้า + คุณ ถ้าเจอข้อใดข้อหนึ่งและแก้ไม่ได้ใน 30 นาที

- เข้าระบบไม่ได้หลายคน / บันทึกไม่ได้ทั้งบริษัท
- ตัวนับโควตาใกล้เต็ม (อ่าน > 40,000 หรือเขียน > 16,000 ก่อน 15:00) — เต็มแล้วบันทึกไม่ได้จนโควตาเริ่มใหม่
- ยอดผิด (ตรวจยอดไม่ ✓ หรือยอดไม่ตรงของจริงหลายกอง)

ข้อมูลในระบบใหม่**ไม่หาย** ปิดสวิตช์แล้วเปิดกลับได้

### ขั้นตอนถอย

1. บอกทุกคน **หยุดกดบันทึก** (ชุดที่ขึ้น ⏳ รอส่ง ให้รอส่งให้จบ หรือจดเลขไว้)
2. ปิดสวิตช์: `public/wms-fire-config.js` → `on: false` → commit → push → รอ Actions เขียว
   ระหว่างรอ เครื่องที่ต้องทำงานด่วนเปิด `?fire=off` ได้ทันที (กลับเป็นหน้าเดิมเฉพาะเครื่องนั้น)
3. หัวหน้าเปิด `?fire=live` (แท็บนี้ยังเข้าระบบใหม่ได้) → ปิดวัน / เดือน → ② วางชีตเดิม → ทุกวันที่ยังไม่ ✓ **เรียงจากวันเก่าสุด**: **📋 คัดลอก** → วางที่แถวว่างแรกของชีต Transaction เดิม คอลัมน์ A → กด **✓ วางแล้ว** แล้วทำวันถัดไป
   (แถวเรียงตามลำดับที่บันทึก รูปเดียวกับชีตเดิม · ยอดยกมาไม่ต้องวาง · ไม่ได้วางรายวัน = มีหลายวันให้วาง ตั้งแต่ 21 ธ.ค.)
   ปิดสวิตช์แล้ว หน้ารายงานกลับไปอ่านชีตเดิม ตัวเลขถูกเมื่อวางครบทุกวัน
4. ทุกเครื่องรีเฟรช → หน้าสมุดสต๊อกเป็นแบบเดิม (เลือกชื่อ + รหัส) → ทำงานต่อในระบบเดิม
5. เช็คตอนถอยมีชุดไหนส่งค้าง: ถ้าชุดที่บันทึกในระบบใหม่ไม่อยู่ในแถวที่วาง ให้ลงในชีตเดิมเพิ่ม

ถ้าเปิดระบบใหม่ไม่ได้เลย (Google / Firebase ล่มทั้งหมด): ใช้ไฟล์ออเดอร์ของวันนั้นตัดใหม่ในระบบเดิม งานอื่นลงจากใบงาน/แชต แล้วค่อยคัดลอกจากระบบใหม่มาเทียบเมื่อเปิดได้

### เปิดกลับ

ระหว่างถอย มีแถวลงในชีตเดิมที่ระบบใหม่ยังไม่มี ต้องเติมให้ครบก่อนเปิดสวิตช์

1. หัวหน้าเปิด `?fire=live` → แท็บ **ตารางแบบเดิม** → วางแถวที่ลงในชีตเดิมตั้งแต่ถอย
   เรียงคอลัมน์ SKU · LOT · PO · Location เบิก · Location รับ · QTY · รับ/เบิก · Note · Status · RUNNUMBER → บันทึก
2. ปิดวัน / เดือน → ① ตรวจยอด ✓ · เทียบยอดรวมกับหน้า ยอด ณ วันที่ ของระบบเดิม
3. `on: true` → commit → push → ทุกเครื่องรีเฟรช (เครื่องที่เคยเปิด `?fire=off` ให้เปิด `?fire=on`)

ถอยนานหลายวัน: คุยกันก่อน อาจนับเฉพาะโลที่ขยับแล้วใช้ **ปรับยอด** แทนการวางแถวย้อนหลังทั้งหมด

## 5. ปิดเดือน (หัวหน้า ทุกต้นเดือน)

ทำไม: เครื่องใหม่ (โทรศัพท์ใหม่ ล้างเบราว์เซอร์ หรือกด **โหลดสำเนาเครื่องนี้ใหม่ทั้งหมด**) ต้องอ่านเอกสารทุกใบ เดือนละราว 2,600 ครั้ง
ปิดเดือน = รวมเอกสารของเดือนที่จบแล้วเป็นก้อน (ก้อนละไม่เกิน 900 KB เดือนหนึ่งราว 3 ก้อน) เครื่องใหม่อ่านไม่กี่ก้อนแทน

1. วันที่ 1 ของเดือนขึ้นไป หัวหน้าเปิด **ปิดวัน / เดือน → ③ ปิดเดือน** (หรือกดปุ่มในแถว *ปิดเดือน … ได้แล้ว* ในหน้า วันนี้)
2. ปุ่ม **🗄️ ปิดเดือน …** บอกเดือนและจำนวนเอกสาร → กด → ยืนยัน
3. ตารางขึ้นเดือนที่ปิด จำนวนก้อน ขนาด · แถบบนบอกเครื่องใหม่อ่านประมาณกี่ครั้ง

- ปิดได้ทีละเดือนตามลำดับ เดือนปัจจุบันยังปิดไม่ได้ · ลืมไปหลายเดือน กดซ้ำทีละเดือนได้
- **ไม่แก้ ไม่ลบเอกสารเดิม** ยอดไม่เปลี่ยน ไฟล์สำรองยังครบ (สำรองทุกคืนไม่เก็บก้อน เพราะสร้างใหม่จากเอกสารได้)
- กู้คืนจากไฟล์สำรองลงโปรเจกต์ใหม่แล้ว: ก้อนยังไม่มี ระบบดึงทีละเอกสารไปก่อน หัวหน้ากดปิดเดือนซ้ำทีละเดือนจนถึงเดือนก่อน
- เลข TRcloud ที่ใส่หลังปิด เครื่องใหม่ยังเห็นครบ (ดึงเพิ่มเอง)
- เน็ตหลุดกลางทาง = ยังไม่ปิด (ตารางไม่ขึ้นเดือนนั้น) กดใหม่ได้เลย
- ใช้โควตาเขียนเดือนละไม่กี่ครั้ง (จำนวนก้อน + 2)
